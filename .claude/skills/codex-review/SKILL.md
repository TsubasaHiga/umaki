# Codex コードレビュー

featureブランチの変更をCodex（GPT-5.3-Codex）にレビュー依頼し、指摘がなくなるまで修正を繰り返します。

## 手順

1. **ブランチ状態を確認**
   - 現在のブランチが `feature/issue-xxx` 形式であることを確認
   - `feature/` で始まらない場合はエラーメッセージを表示して終了
   - 未コミットの変更がないことを確認（あれば警告）

2. **変更差分を取得**
   - `git diff develop...HEAD` で develop ブランチからの差分を取得
   - 差分がない場合はエラーメッセージを表示して終了

3. **サブエージェントで Codex MCP にレビューを依頼**
   - `Task` ツール（`subagent_type: general-purpose`）でレビュー専用サブエージェントを起動
   - サブエージェントへの指示に以下を含める:
     - 取得した diff の全文
     - プロジェクトの技術スタック（TypeScript strict, Vite, Vitest, Biome, ESM/CJS dual output）
     - ライブラリ特有の観点（後方互換性、API破壊的変更検出、型定義品質）
     - レビュー重点ポイント（$ARGUMENTS が指定されている場合はそれを追加）

4. **レビュー結果をユーザーに提示**
   - Codex からの返答をそのまま表示
   - サマリー（Critical/Warning/Info/Good の件数）を強調表示
   - Critical または Warning が 0 件の場合は「レビュー通過」を通知

5. **レビュー結果の精査（重要）**
   - Codex の指摘を**鵜呑みにしない**。各指摘を深く理解し、妥当性を判断する
   - 各指摘について判断: 妥当→修正 / 妥当だが別解あり→相談 / 的外れ→スキップ
   - ユーザーに精査結果と対応方針を提示し、承認を得てから修正を実施

6. **修正・再レビューループ**
   - 承認された修正を実施
   - 修正完了後、再度差分取得→再レビュー
   - Critical/Warning が 0 件になるまでループ（最大3回）

7. **完了**
   - 最終レビュー結果のサマリーを表示

## ライブラリ特有のチェックポイント

- **後方互換性**: エクスポートされた関数のシグネチャ変更、型定義の変更
- **破壊的変更**: 既存APIの動作変更、デフォルト値の変更
- **型定義品質**: 適切な型付け、`any`の回避、ジェネリクスの活用
- **エクスポート**: 新規関数のindex.tsへのエクスポート漏れ
- **テスト**: 新規/変更された関数のテストカバレッジ

## 注意事項

- レビュー結果の修正はユーザー承認後に行う
- 修正時は CLAUDE.md のコーディング規約に従う
- Codex MCPが利用不可の場合はエラーメッセージを表示して終了
